# 프로젝트 구조와 설계 의도

이 프로젝트는 네이버 블로그 음식 사진에서 원본 음식·용기 픽셀을 보존하고, 음식이 없는 업종별 광고 배경을 생성·합성하는 모듈이다.

```text
입력
→ 학습한 음식 전용 YOLO11n(`models/best.pt`) 탐지
→ SAM 2.1 Tiny 구조 마스크
→ BiRefNet 품질 검사형 미세 보정
→ 원본 전경 RGBA
→ Sana 또는 FLUX 빈 배경
→ 그림자·경계·밝기 조화
→ OpenCLIP 검증
→ 통과한 결과만 광고 JPG 저장
```

## 안전 경계

- 음식 탐지 기본 프로필은 `food_specialized`다. 기본 COCO YOLO11n은 `coco_yolo11n` 프로필을 명시적으로 선택한 경우에만 사용한다.
- 중앙 사각형은 `--diagnostic-center-fallback` 연결 테스트에서만 사용한다.
- SAM 마스크는 합성 전에 닫힘 연산, 작은 연결 요소 제거, 내부 구멍 채우기를 적용한다. 원본 SAM 마스크는 디버그용으로 별도 보관한다.
- BiRefNet은 안정화된 SAM을 대체하지 않는다. IoU, 면적 비율, 연결 요소 수 검사에 실패하면 안정화된 SAM 마스크를 사용한다.
- OpenCLIP은 전경 마스크 바깥을 동일한 중립색으로 제거한 비교 이미지로만 유사도를 계산한다. 새 배경 자체는 유사도 하락 원인이 아니다.
- OpenCLIP 유사도가 0.8 미만이면 SAM으로 재합성한다. 다시 실패하면 원본 반환 경로로 종료하고 광고 이미지를 저장하지 않는다.

## 폴더

- `app/pipelines`: 전체 실행 순서와 실패 보고서 생성
- `app/services`: 탐지·분할·매팅·생성·합성·검증 모델 어댑터
- `configs`: 일반 파이프라인 모델과 처리 정책 설정
- `scripts`: 일반 실행, 모델 다운로드, YOLO11n 학습·평가 실행
- `notebooks`: 코랩 및 로컬 전체 검증
- `docs`: 설치·구조·학습·네이버 연동 문서

## 필수 디버그 산출물

성공 또는 검증 실패 보고서에는 원본·안정화 SAM 마스크, BiRefNet/SAM 알파, RGBA 전경 미리보기, OpenCLIP 전경 비교 이미지, 최종 또는 거부된 합성 이미지 경로를 `debug_artifacts`로 저장한다.

## 각도·후보·기하 검증 계층

배경 생성 전에는 `models/efficientnet_best.pt`의 EfficientNet-B0가 입력을 `top` 또는 `45`로 분류한다. JSON에서 `camera_angle_manual: true`와 `camera_angle_label`을 지정하면 분류 결과보다 JSON 값을 우선한다.

```text
각도 판별 또는 JSON 지정
  → 각도 제약이 적용된 업종별 빈 배경 프롬프트
  → 서로 다른 시드의 배경 후보 3~4장
  → 중앙 여백·색온도·배경 음식 탐지 점수로 후보 선택
  → 원본 전경을 캔버스 너비 55~70%로 재배치
  → 각도별 접지 그림자·9px feather·제한된 색 조화
  → OpenCLIP 전경 보존 + 배경 음식 + 기하 검증
```

`top`은 수직 테이블 배경과 중앙 배치, 약한 원형 그림자를 사용한다. `45`는 사선 테이블·실내 배경과 하단 중앙 배치를 사용한다. 생성 배경에서 음식이 검출되거나 전경 배치 비율·위치가 정책을 벗어나면 결과 JPG를 저장하지 않는다.
